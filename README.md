# 猫脳社（NEKONOSHA）

猫たちが AI 社員として働く、レトロなピクセルアートのオフィス管理アプリです。

## はじめ方

Node.js 20.9 以上（推奨：Node.js 24 LTS）を用意し、ターミナルでこのフォルダを開いて実行します。

```bash
npm install
npm run dev
```

ブラウザで http://localhost:3000 を開きます。停止するときはターミナルで `Control + C` を押します。

iPhone で見る場合は Mac と同じ Wi-Fi に接続し、起動ログの `Network` に表示される URL を Safari で開いてください。必要に応じて Mac のファイアウォールでローカル接続を許可します。

## できること

- 広告事業部・EC 事業部の切り替え
- 社長猫「しらす」と秘書猫「ぽんず」がいるドット絵オフィス
- タスクの未着手・作業中・確認待ち・完了の切り替えと進捗表示
- ぽんず秘書への仕事依頼（下の「ぽんずへの仕事依頼」を参照）
- サンプル通知の既読操作
- Mac・iPhone 向けのレスポンシブ表示

## ぽんずへの仕事依頼

「秘書のデスク」に自然な日本語で依頼すると、仕事名・事業部・担当猫・期限候補・具体的な作業内容を整理し、登録前プレビューを表示します。APIキー未設定時は従来のルールベース解析、設定時はOpenAIによる解析を使います。成果物と品質レビューは引き続きサンプルです。

1. 「来週までに秋のキャンペーン企画をまとめて」などと入力します。
2. 部署・期限・作業内容などが不明なときは、ぽんずが確認質問を表示します。下の編集欄で回答できます。
3. 仕事名・事業部・成果物の種類・期限・作業内容を確認、修正します。担当猫は仕事内容からぽんずが自動選定し、必要なら同じ事業部の協力猫も選びます。手動の担当選択はありません。元の入力を変えた場合はプレビューを作り直してください。
4. 「依頼内容を承認して作業開始」を選びます。未承認のプレビューはタスク数にも猫の動きにも影響しません。
5. 担当チームが初版を提出すると、しらす社長が完成条件・期限・依頼への対応・サンプル表記をチェックし、具体的な修正コメントを表示します。
6. 必要ならぽんず経由で社内修正し、再レビュー後にぽんずがユーザーへ報告します。ユーザーの最終承認で初めて完了になります。ユーザーの修正依頼もぽんずが受け、作業と社長レビューをやり直します。

担当猫の専門分野は、こはく＝営業企画、みつまめ＝制作・デザイン、むぎ＝メディア・PR、くろごま＝リサーチ、おもち＝事務サポートです。複数の専門分野が必要な場合はチームで協力し、主担当が1つのサンプル成果物を取りまとめます。

4種類のタスク状態は維持し、作業中を「担当チーム作業・しらす社長レビュー・社内修正」に分けて表示します。社長レビュー中は、既存のオフィス入力を通じてしらすが作業状態になります。画像や動きのコードは変更していません。

品質レビューは試作の定型チェックです。初版にない品質確認メモを社内修正で追加し、提出版の内容を再チェックします。自動修正はユーザー確認の各ラウンドで1回までです。指摘が残る場合もユーザーへ判断を戻し、無限に修正しません。しらすのチェック通過で自動完了したり、最終承認を代行したりすることはありません。

- 期限は今日・明日・明後日・日付指定・曜日・来週の曜日などに対応します。曜日のない「今週・来週・再来週」はその週の金曜日、週末は日曜日を候補とし、プレビューで変更できます。基準日は画面上部のデモ日付（2026/10/25）です。未指定・不正な日付は確認質問になります。
- どちらの部署か判断できない場合や、複数部署が指定されている場合は部署の選択を求めます。1件につき1部署とし、両部署の仕事は分けて依頼してください。
- 入力と編集中のプレビューは受付の部署ごとに保存します。部署を切り替えると、その部署の入力・プレビューを表示します。登録後は確認した担当部署のタスク一覧に入り、依頼一覧・成果物・通知・秘書の返信も部署別に表示します。
- 担当猫は数十秒のデモ用作業時間のあいだ、既存のオフィスで「依頼対応中」になります。全体マップの札や会議・休憩の制御も既存の仕組みを使います。
- 成果物はローカルの定型文によるサンプルです。具体的な作業内容は受付メモとして成果物にも残しますが、自由文の業務を実際に遂行するものではありません。メール送信・SNS投稿・外部公開は、登録や承認後も一切行いません。
- `app/components/requests/intake.ts` の `RequestInterpreter` が解析の境界です。解析は編集用の `RequestDraft` を返し、`confirmDraft` が承認した内容から自動振り分けを再計算して `WorkRequest` を作ります。`assignment.ts` が担当選定、`quality.ts` が品質チェック、`requests.ts` が進行と承認を管理し、画面・保存から分離しています。

## ぽんずのOpenAI接続

- `POST /api/ponzu/analyze` は同じサイトの画面から `{ text, department }` だけを受け取り、`{ mode: "demo" | "openai", proposal }` を返します。提案には `summary`、`questions`、`department`、`kind`、`recommendedStaff`、`dueDate`、`details`、`explanation` を含みます。タスクID・承認状態・実行命令・ワークフローの追加は検証で拒否します。
- `app/lib/ponzu/contracts.ts` がJSON Schemaと実行時検証、`server.ts` がデモとAIの切り替え、`openai.ts` がOpenAI Responses APIへの送受信と回答検証、`client.ts` が画面との通信を担当します。サーバー専用モジュールは `server-only` でブラウザへの取り込みを防ぎます。AIの推奨担当は確認画面に反映され、仕事内容を編集した場合は変更内容からルールで再選定します。
- `OPENAI_API_KEY` はサーバー側の環境変数としてのみ参照します。`.env.local` は既存の `.env*` ルールでGit管理対象外です。`.env.example` は空欄の説明用で、実際のキーを記入して共有しないでください。`NEXT_PUBLIC_` のキー変数は使いません。
- キーが空または未設定なら、外部通信なしのデモです。キーが設定されている場合にだけ、サーバーからOpenAIへ依頼文と表示部署を送ります。モデルはサーバー環境変数 `OPENAI_MODEL` で変更でき、省略時は `gpt-5.4-mini` です。Responses APIとStructured Outputsに対応するモデルを指定してください。`.env.local` はこの開発作業では作成・変更していません。
- 依頼文は非信頼データとして扱い、提案の許可された項目だけをプレビューに反映します。提案APIにはタスクを変更する機能がなく、ユーザーが承認ボタンを押した時だけ画面側で依頼を検証し、タスクと進行状態を作ります。依頼文で「承認済みにして」と指示しても承認を代行しません。
- APIは入力形式・部署・文字数・本文サイズ・異なるOriginを検査し、レスポンスをキャッシュしません。例外の内容・キー・環境変数・依頼文をログに出す処理は追加していません。エラー応答は固定文です。画面から送るのは今回の依頼文と部署のみで、他部署のタスクや成果物は送りません。
- 25秒のサーバー側タイムアウト、応答サイズ上限、回答拒否・不完全な回答・不正なJSONの検査があります。通信や検証が失敗したら固定の分かりやすいエラーを表示し、自動でデモへ切り替えたりタスクを登録したりしません。「もう一度解析する」か「デモ解析を使う（外部通信なし）」を選べます。エラー中は以前の提案も承認できません。部署切り替え時は処理を中断し、古い応答で別部署のプレビューを更新しません。
- 連続した有料呼び出しは、サーバープロセス全体で同時1件・最低3秒間隔・60秒の固定枠で6件までに制限します。失敗も回数に含み、自動再試行はしません。制限時は429と待ち時間を返します。サーバー再起動で回数はリセットされます。複数サーバーでは各々の上限になるため、公開運用には認証と共通の利用制限・予算管理を別途設けてください。
- `node scripts/tests/ponzu-api.mjs` はダミー資格情報だけをテストプロセス内で使い、外部通信を禁止して検証します。実キーや `.env.local` は変更しません。既存の回帰テストは `node scripts/tests/workspace.mjs` です。

### 設定と動作確認（後でご自身で行う場合）

1. デモだけを確認する場合はキーを設定せず、`npm run dev` を実行します。依頼を解析するとデモの提案が表示され、承認するまでタスク数は変わりません。
2. 実際のAIを使う準備ができたら、プロジェクト直下の `.env.local` に `OPENAI_API_KEY` を設定します。必要なら `OPENAI_MODEL` も設定します。変数名と空欄の見本は `.env.example` にあります。キーをチャットやGitに貼り付けないでください。
3. 開発サーバーを停止して `npm run dev` で起動し直します。設定したキーで「ぽんずにお願いする」を押すと課金対象の通信が発生します。まず1件だけ試し、「OpenAIによる提案です」の表示と内容を確認してください。
4. 不足情報があれば入力し、提案を確認してから「依頼内容を承認して作業開始」を押します。成果物・しらす社長のレビューは従来のサンプル動作です。メール送信・SNS投稿・外部公開はありません。
5. 設定の誤り・混雑・回答拒否・タイムアウトではエラーが表示されます。再試行は別の呼び出しになるため、連打せず待ってから操作してください。通信せず進めたい場合は「デモ解析」を選んでください。

キーなしで実行できる確認コマンド：

```bash
npm run typecheck
npm run lint
node scripts/tests/ponzu-api.mjs
node scripts/tests/workspace.mjs
npm run build -- --webpack
```

AI接続テストは模擬通信で、実際の有料APIは呼びません。実キーでの疎通・モデル利用権限は別途確認が必要です。参照した公式仕様：[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)。

## 全体マップ

オフィス欄の「全体マップ」で、5つの部屋を1つの建物にまとめ、斜め上から床・壁・家具が見えるアイソメトリック（3/4）視点の昼間のオフィスとして表示します。建物は芝生広場（小さな花・木・ベンチ）の中に建ち、奥には雪をかぶった富士山と青空・白い雲が見えます。空と芝生は画面の端で水平な帯になっていて、ステージより広い画面では枠の左右にもそのまま続きます。奥の2面は窓のある白い壁、部屋の間は低い白壁とガラスの間仕切りです。家具（デスク、ソファ、会議テーブル、受付カウンター、コーヒーバー、本棚など）は、この視点に合わせてマップ用に描き直しています。エッグチェアとビーズクッションは各部屋と同じ絵を使い、猫との大きさをそろえています。

- **配置**：奥の左が社長室（一段高く、階段で廊下へ）、中央がガラス張りの会議室、右がワークスペースです。手前の左が受付（ロゴの壁・カウンター・WELCOMEマット）、中央がラウンジです。部屋の間をオレンジのラインの廊下がつなぎ、各部屋のドアは廊下に面しています。
- **猫の動き**：担当タスクがある猫はワークスペースのデスクで作業し、ない猫はラウンジ（ソファ・エッグチェア・ビーズクッション）で休みます。タスクを完了・未完了にすると、ドアと廊下を通って歩いて移動します。作業中の猫は交代でコーヒーを飲みに行き、1分ごとに3匹ずつ会議室で打ち合わせをします。お客さまは受付→待合→会議室（社員の会議に同席）→お帰りの順に動き、次のお客さまに交代します。猫は壁・ガラス・家具を通り抜けず、必ずドアから出入りします。ガラスの向こうにいる猫はガラス越しに、廊下を歩く猫はガラスの手前に描きます。「一時停止」で止められ、動きを減らす設定のときは歩かずに移動します。
- **社長室**：詳細画面と同じ2人用の横長デスクに、しらす（左）とぽんず（右）がエッグチェアで向かい合って座り、それぞれ正面のノートPCでタイピングします。デスクと2匹の配置は `executive-desk.tsx` を社長室画面と共有しています。
- **タイピング**：ワークスペースの5匹の席は、モニターを猫に向けた机とオフィスチェアです。猫は画面のほうを向き、キーボードの上で左右の前足を交互に動かします。打つリズムに合わせて頭が小さく揺れ、ときどき耳が動きます。しばらく打つと手を止めて顔を上げ、画面を見てまばたきしてから再開します。モニターは猫ごとにコード・グラフ・文書の画面で、打った内容が増えて行がスクロールします。猫は体・頭・手前の前足・奥の前足・しっぽの別々の PNG（`public/office/cats/<猫のID>/type-*.png`）で、同じ48コマの時間軸で動き、猫ごとに開始をずらしています。タイピングは PC の前に座っているときだけで、席を離れると歩く・休む・話すに切り替わります。席が空くとモニターはスクリーンセーバーになります。
- **共通スケジュール**：会議・コーヒー休憩・来客の時間割は `app/components/office/office-schedule.ts` の1つの時計で決まり、全体マップとすべての詳細画面が同じものを読みます。同じ猫がある画面では会議中、別の画面では作業中、ということは起きません（全体マップでは移動の数秒だけ「移動中」になります）。
- **詳細画面**：部屋の床をクリック（タップ）すると、その部屋の詳細画面に切り替わります。
- **猫の情報**：猫や下の名前ボタンを押すと、名前・役職・いる場所・いまの仕事を表示します。
- **表示倍率**：倍率は画面に合わせて自動で決まり、ユーザーは変更できません。ドットがにじまないよう実ピクセル単位でそろえ、Mac では全体を画面幅いっぱいに表示します。iPhone では約2/3倍で表示し、建物の中央から始まります。はみ出す分は左右にスクロールできます。
- 部屋・壁・ドア・家具・席・通り道は `app/components/office/office-map.json` にワールド座標（u・v）で書いています。画面と動きは `office-map.tsx`、倍率は `use-map-scale.ts` です。
- 建物・壁・家具の PNG は `scripts/office-art/office-map.mjs` から `public/office/map/` に生成し、家具の基準点と壁の分割は `office-map-sprites.json` に自動で書き出します。

オフィス・成果物・品質レビューはサンプルデータです。依頼の整理はAPIキー未設定時にデモ、設定時にOpenAIを使います。データベース、メール送信、課金サービスの操作は接続していません。タスク・依頼・成果物・修正履歴・部署別の入力とプレビューは、同じブラウザ・同じURLの localStorage（`nekonosha.workspace`、形式バージョン4。バージョン1・2・3も読み込み可能）に保存し、再読み込み後も復元します。作業中の依頼は保存された開始時刻を引き継ぎ、作業時間が経過していれば次の段階へ進みます。担当チーム・進行段階・品質レビュー履歴も保存します。旧形式の依頼は、既存の成果物と承認状態、従来の進行を維持します。旧形式の `done`（false→未着手、true→完了）と `approved`（完了）も読み込めます。保存できない場合は画面に警告を表示します。破損データや未対応の新しい形式は上書きせず、読み込みエラーを表示して編集を停止します。通知・秘書の会話履歴・表示中の部署は保存対象に含みません。ブラウザの保存データを削除すると初期状態に戻ります。表示日付・通知時刻・出勤状況もデモ用です。

## 社長室（新デザイン試作）

オフィス欄の「社長室（新デザイン試作）」で、参考画像をもとにした3/4見下ろし視点の16bit風社長室を表示します。「全体マップ（現行）」で従来のマップに戻せます。

- 背景・照明・家具・猫（体、まばたき、しっぽ）・椅子の前後パーツは、すべて別々の PNG（`public/office/president/`）です。
- 配置と重なり順は `app/components/office/president-room.json` で管理しています。座標はドット絵の 320×180 ピクセル基準で、画面幅に合わせて整数倍に拡大します。
- PNG は `npm run art:office` でコード（`scripts/office-art/`）から生成しています。同じファイル名・サイズで Aseprite などの手描き PNG に差し替えることもできます。
- 2人用の横長デスク（中央に観葉植物とマグカップ）をはさんで、しらすとぽんずがエッグチェアで向かい合います。担当タスクが残っていれば正面のノートPCに前足を置き、左右交互にタイピングします。担当がなくなると椅子で居眠りし、ノートPCは待機画面になります。
- 大きな窓からは、昼の青空と雲、富士山、花の咲く芝生広場とベンチが見えます。作業スペースの窓（富士山は左端の窓）、ラウンジの丸窓、受付のガラスの入口も同じ昼の景色です。景色は `scripts/office-art/daylight.mjs` で全部屋と全体マップに共通の描き方をしています。会議室は外に面した窓がないため（全体マップでも同じ）、景色は入れていません。

## 作業スペース（新デザイン試作）

オフィス欄の「作業スペース（新デザイン試作）」で、社長室と同じ画風の作業スペースを表示します。

- こはく・みつまめ・むぎ・くろごま・おもちの5匹がデスクに座り、デスクの札は広告事業部／EC事業部で切り替わります。
- 選択中の事業部のタスクを、上から順に5匹で分担します（6件目以降は再びこはくから）。未完了の担当があればノートPCに向かってタイピングし、なければ入口から出てラウンジへ休みに行きます。会議・コーヒー休憩の時間も共通スケジュールどおりに席を外し、名前ボタンには「会議中」「コーヒー休憩」「休憩中」と表示します。
- 表示直後から、共通スケジュールのいまの状態で始まります（席の猫は座った状態）。
- 猫や下の名前ボタンを押すと、名前・役職・担当タスク・状態を表示します。
- 配置は `app/components/office/work-studio.json`、画像は `public/office/studio/`（椅子とノートPCは社長室と共通）です。

## 会議室（新デザイン試作）

オフィス欄の「会議室（新デザイン試作）」で、ガラス張りの会議室を表示します。オレンジの楕円テーブル、チューリップチェアとエッグチェア、壁面モニター（スライドが切り替わります）、ホワイトボード、観葉植物、UFO型のペンダントライトを配置しています。

- 共通スケジュールで会議中の猫（最大3匹、毎回交代）だけが席に着き、来客中はお客さまも同席します。会議がないときは空室で、次の会議までの秒数を表示します。約4.5秒ごとに発言者が交代します。発言中の猫は手ぶりと口の動きで話し、吹き出しに担当タスクの進捗（担当がなければ事業部ごとのサンプル発言）を表示します。
- 担当タスクが残っている猫は資料を読み、担当がない猫はうなずきます。タスクの分担は作業スペースと同じです（`app/components/office/staff.ts`）。
- 猫や下の名前ボタンを押すと、名前・役職・担当タスク・いまの様子を表示します。一時停止中は発言者も交代しません。
- 配置とサンプル発言は `app/components/office/meeting-room.json`、画像は `public/office/meeting/` です。

## 受付（新デザイン試作）

オフィス欄の「受付（新デザイン試作）」で、猫脳社のロゴ入りカウンターがある受付を表示します。ガラスの入口、ペンダントライトとアーチ型フロアランプ、観葉植物、待合のエッグチェア、ラウンジへの通路を配置しています。

- 受付係のハチワレ猫「きなこ」がお客さまを迎えます。お客さまは入口から歩いてきて、カウンターであいさつ（手ぶり→おじぎ）を受け、待合で資料を読んで待ち、ラウンジ側の通路から会議室へ向かいます。会議が終わると通路から戻り、入口からお帰りになります。時間割は全体マップと同じ共通スケジュールで、2組のお客さまが交代で来ます。
- 猫や下の名前ボタンを押すと、名前・役職・担当（受付係は来客対応、お客さまはご用件）を表示します。
- 配置・お客さま・セリフは `app/components/office/reception.json` です。

## ラウンジ（新デザイン試作）

オフィス欄の「ラウンジ（新デザイン試作）」で、オレンジのソファ、丸テーブル、コーヒーマシン、丸窓のあるラウンジを表示します。

- 担当タスクがない猫は作業スペース側の通路から歩いてきて、ソファ・エッグチェア・ビーズクッションで休みます。ソファの猫は交代でおしゃべり（もう1匹は相づち）、コーヒーをひと口、うたた寝をします。
- 作業中の猫も共通スケジュールで交代にコーヒーを淹れに来て、デスクへ戻ります。タスクを完了・未完了にしたり、ぽんずに指示を出したりすると、猫がラウンジとデスクの間を移動します。
- 配置とおしゃべりのセリフは `app/components/office/lounge.json` です。

## エリア共通の仕組み（オフィスマップに向けて）

受付とラウンジは、将来すべての部屋を一つのオフィスマップにつなげられるよう、共通の形式で作っています。

- **エリア定義（JSON）**：大きさ・歩く通路の高さ（`walkY`）・ドア（`doors`、`to` に隣の部屋のID）・家具（`props`、床に接する高さ `base` で前後を決定）・猫の居場所（`spots`）を持ちます。座標は部屋ごとのローカル座標なので、マップでは部屋ごとの原点を足すだけで配置できます。
- `area.ts`：エリアの型と、ドア・居場所から目的地の座標を引く `areaIndex`
- `movement.ts`：歩行（通路経由のルート、移動、目的地の変更）。作業スペースも同じものを使っています。
- `cat-sprites.ts`：猫の全ポーズの画像の場所。どのエリアからでも同じ猫を描けます。
- `area-stage.tsx`：エリアの描画枠、エッグチェアやビーズクッションに座る猫、吹き出し、名前ボタン、詳細カード
- `office-areas.ts`：オフィス欄の切り替えボタンになる部屋の一覧

画像は `public/office/reception/`・`public/office/lounge/`、新しく描いた猫のポーズは部屋に依存しない `public/office/cats/<猫のID>/` に置いています。

## 開発用コマンド

```bash
npm run lint
npm run typecheck
node scripts/tests/workspace.mjs
npm run build
npm start
```

`npm start` はビルド後の本番用サーバーを起動します。通常の編集には `npm run dev` を使います。

## 構成

- `app/page.tsx`：画面、サンプルデータ、操作
- `app/globals.css`：Tailwind CSS の読み込みと画面・家具のスタイル
- `app/layout.tsx`：日本語設定とページ情報
- `app/components/office/`：全体マップと、社長室・作業スペース・会議室・受付・ラウンジ（試作）の描画・配置データ、エリア共通の仕組み
- `scripts/office-art/`：ドット絵 PNG の生成スクリプト

Next.js App Router・TypeScript・Tailwind CSS v4 を使用しています。オフィスの絵はリポジトリ内のドット絵 PNG（`npm run art:office` で生成）とインライン SVG・CSS で描いているため、画像配信サービスや外部フォントへの接続も必要ありません。
